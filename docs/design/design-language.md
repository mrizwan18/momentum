# Momentum Design Bible

## Volume II --- Design

### Chapter 1: Design Language & Emotional Experience

Version 1.0

# Design Mission

Momentum should feel like sitting down with a trusted coach in a quiet
practice room.

Not a game. Not a dashboard. Not a spreadsheet.

It should communicate calm confidence.

---

# Design Keywords

- Calm
- Premium
- Focused
- Warm
- Encouraging
- Minimal
- Human

Reject: - Busy - Flashy - Noisy - Competitive - Overwhelming

---

# Emotional Matrix

Screen Enter Feeling Exit Feeling

---

# Visual Grammar

Every screen should follow the same visual rhythm.

1.  Context
2.  Primary Metric
3.  Primary Action
4.  Supporting Information
5.  Historical Context

Never place analytics above the primary action.

---

# Information Density

Maximum:

- 1 Hero
- 1 Primary CTA
- 3 Supporting Cards
- 1 Secondary Section

If more information exists, move it behind progressive disclosure.

---

# Color Psychology

Warm Orange - Achievement - Progress - Action

Muted Teal - Guidance - Coaching - Learning

Green - Completion

Red - Reserved for destructive actions only

Never use red to indicate poor performance.

---

# Typography Rules

Headlines motivate.

Body explains.

Captions reassure.

Numbers deserve emphasis.

Never use more than three font weights on one screen.

---

# Motion Language

Motion must communicate state.

Examples: - Fade = appearance - Slide = navigation - Scale =
achievement - Pulse = active recording

Avoid decorative animation.

---

# Empty States

Every empty state includes:

- Explanation
- Encouragement
- Single CTA

Example:

"No recordings yet.

Your first recording becomes the beginning of your Voice Timeline."

CTA: Record Today

---

# Loading States

Skeletons over spinners.

Optimistic UI where possible.

Never block the user unnecessarily.

---

# Error States

Tone:

Calm.

Helpful.

Actionable.

Example:

"We couldn't save that recording.

Nothing has been lost.

Try again."

---

# Accessibility

- 44px touch targets
- WCAG AA contrast
- Reduced motion
- Keyboard support
- Screen reader labels

Accessibility is a design requirement, not a feature.

---

# First Impression Test

Within five seconds a new user should understand:

1.  This app helps me practice.
2.  I know what to do next.
3.  My progress will be visible.
4.  This feels welcoming.

If any answer is unclear, redesign the screen.

---

# Chapter Summary

The interface should quietly disappear behind the user's practice.

Every design decision should help users spend less time navigating and
more time improving.
